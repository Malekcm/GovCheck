# GovCheck BD audit — October 2026

Standard applied: *"If I relied on GovCheck every morning to decide what federal opportunities my company should pursue, what could I be missing, what could mislead me, and what would make me trust it?"*

Method: read every server/client module, ran `lint`, `typecheck`, `test`, `build`, and ran every keyless connector against the **live** government endpoints (GSA Acquisition Gateway, DHS APFS, USAspending, SBA SUBNet, Grants.gov) into an isolated database, then exercised the UI. SAM.gov paths were verified with recorded fixtures (no key available during the audit). The per-source field matrix is in [`SOURCE_COVERAGE.md`](SOURCE_COVERAGE.md).

## 1. What was already genuinely working

- Clean baseline: lint, typecheck, 44 tests and build all passed.
- Raw-record durability: verbatim raw JSON, every distinct version kept, content-hash skip, parser-version re-normalization, `not_seen` marking instead of deletion.
- Field-level provenance (official / derived / estimated / AI / user) with conflicts preserved and a sound precedence rule (AI and estimates never beat official values).
- Conservative entity resolution: only strong identifiers auto-link; solicitation numbers require compatible agencies; placeholders never match; probabilistic matches are only *suggested*; merges are journaled and reversible.
- Explainable fit score with configurable weights, eligibility kept separate (never "ineligible" on text-only evidence), preference learning that never modifies base fit.
- Budget-aware, resumable SAM ingestion; robots.txt-respecting SUBNet reader; failure isolation per connector.
- All keyless connectors still match the live APIs/pages.
- User data (decisions, notes, tags, overrides, manual links) is never written by sync.

## 2. What was broken, incomplete or misleading

| Finding | Impact for a BD lead |
|---|---|
| GSA forecast API returns page 2 as a copy of page 1 (verified live, repeatedly) | ~25 forecasts per affected page silently invisible while the source showed **healthy** |
| No DHS forecast coverage (APFS has a public API with contacts + incumbents) | Missed the richest public forecast in the market |
| USAspending recompete scan ignored IDVs (IDIQ/GWAC/BPA/FSS) | Expiring vehicles — the biggest recompetes — never surfaced |
| No scope/description change detection; no cancellation detection; no "solicitation released" event | "What changed?" missed requirement edits and cancellations |
| "Best" sort ranked by raw fit | A keyword-perfect 8(a) set-aside you cannot bid could top the list |
| No attractiveness / confidence dimensions | Thin one-line forecasts looked as trustworthy as full solicitations |
| GSA "Exercise of Option" forecasts treated as opportunities | Not competitions at all |
| Decisions limited to Pursue/Interested/Watch/Maybe/Pass/Not relevant | No way to record "Not eligible"/"Duplicate" without poisoning the preference model |
| No capture pipeline (owner, next action, stage) | Tool stopped at "interesting", not "what do we do Monday" |
| Merge did not move user field overrides | Overrides on a merged-away profile silently stopped applying |
| Requirement rules missed CMMC, FedRAMP, NIST 800-171, 508, citizenship, experience, bonding, transition, sole-source | Hard gating requirements invisible without AI |
| Document classifier matched "amendment" anywhere in the first 3,000 chars | Most RFPs mis-classified as amendments |
| SSRF: custom feed URLs and document links could target internal addresses (incl. cloud metadata) | Security exposure on hosted deployments |
| CSV export: no formula neutralization; silent 20,000-row truncation | CSV-injection risk from external titles; silently incomplete exports |
| No data-quality view beyond a health dot | No way to tell whether GovCheck is actually seeing the market |

## 3–10. What changed

See the commit history on branch `govcheck-bd-audit` and README. Summary:

- **New source:** DHS APFS (`dhs_apfs`).
- **Improved sources:** USAspending (IDVs), GSA (coverage measurement, option-exercise flag), SAM (cancellation, J&A/sole-source, POC additional info).
- **Schema (migration 003, additive only):** `opportunity_capture`, `opportunity_capture_history`; `attractiveness_score`, `confidence_score`, `priority_score` on opportunities/match scores (+ `dimensions` JSON); `opportunity_requirements.strength`; 13 indexes for scale.
- **Scoring:** company fit (unchanged), eligibility (unchanged), **strategic attractiveness**, **data confidence**, **review priority** with eligibility caps; default sort = review priority.
- **Change detection:** SCOPE_CHANGED (with added text), DATES_CHANGED, SET_ASIDE_CHANGED, SOLICITATION_RELEASED, CANCELLED, QA_PUBLISHED, amendment documents — upgrade-safe.
- **BD workflow:** expanded decisions + reasons; capture pipeline page; recommended next actions; saved views; pursuits-changed queue; expiring-contracts page; data-quality page.
- **Exports:** Excel workbook with provenance legend, changes CSV, full dossier JSON, source/provenance JSON (raw records + every version), Markdown capture brief, larger backup (capture, manual award links, dismissed signals).
- **Security:** SSRF guard (DNS-resolved, every redirect), formula neutralization, explicit truncation marker.
- **Tests:** 28 new tests in `tests/bd.test.ts` (72 total).

## Highest-value next enhancements

1. **Higher SAM quota** (role/system account) + daily bulk reconcile + attachment downloads for fit ≥ 60 — the single biggest coverage and document-intelligence gain.
2. **Agency forecast feeds** beyond GSA/DHS (VA, HHS, DOE, NASA, Treasury, DoD components) via the custom feed connector where official files exist.
3. **USAspending subawards + transaction history** for teaming intelligence and option/modification timelines.
4. **OCR** for scanned PDFs behind the existing `ocr_needed` status.
5. **Multi-user identity** (owner = real user, per-user notifications/digests) — currently a single shared password.
6. **Daily email/Teams digest** of "your pursuits changed", new high-priority items and overdue capture actions.
7. **Semantic matching** (embeddings via pgvector) behind the existing similarity interface.
